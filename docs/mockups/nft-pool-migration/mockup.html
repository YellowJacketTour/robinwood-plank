Standard vault fees (mint 1%, redeem 1%) — the exact same fees as any other day. There is no special migration charge.

What can never happen

  • Your planks can't be taken. Redeem always hands the NFT to your wallet before anything else happens.
  • No admin can touch pool ETH — on V1 or V2. That's why V1's seed ETH stays behind, by design.
  • Stopping mid-way is safe. A redeemed plank simply sits in your wallet until you deposit it.

Built-in rescue, no dead ends

V1 allows one pending random redeem at a time, vault-wide. The page detects all three cases: yours pending → "Finish my redeem" (relay round + claim); someone else's → "Settle it for them" (they get their plank, slot frees up — costs you only gas); expired >24h → "Clear expired request". The step turns into whichever rescue applies instead of a raw revert message.

D · Implementation notes (what each control actually calls)

Wiring the mockup to the code that already exists

Detection — one hook, useV1Position(account): getVaultOnChainSnapshot(legacyAddr, account) (shares, poolOpen), pendingRequester()/pendingRound() (slot state), getOwnedInventory (planks in wallet). Drives the banner, the scan card, and every step gate. Single 20s poll shared via context — replaces today's duplicated polls.

Step "Redeem" — requestRandomRedeem() on V1, then the existing sponsor path (/api/market/vault/settle-random) with client fallback finishRandomRedeem (beacon submitRound + claimRandomRedeem). The monitor rows map 1:1 to the onProgress phases that already exist in lib/market/vault.ts.

Step "Deposit" — existing depositForShares: per-token approve then deposit(tokenId) on V2 (never setApprovalForAll). Queue loops redeem→deposit per plank; progress chips persist in localStorage so a returning wallet resumes where it left off (on-chain balances remain the source of truth).

Dust exit — sellShares on V1 with a live quote + slippage guard; top-up path reuses the migrate panel's buyShares dust logic but with user-visible min-out instead of the hard-coded 200bps.

Rescue — lift PendingRedeemClaim / StuckRedeemRelay out of SwapPanel into shared components; render inline as the step body when the slot is busy. forfeitExpiredRedeem gated behind a confirm that explains the share goes to treasury.

Sunset (guided-hard) — InstantVaultSwitcher collapses to V2-only; SwapPanel loses the V1 retarget; the old migrate <details> in MarketView becomes a link card to /migrate; V1 stays in env + tx allowlist (removing it bricks every V1 call — the registry warns about exactly this); VaultTradeHistory keeps showing V1 history. Feature flag per CAP-E7: NEXT_PUBLIC_MIGRATION_MODE = off | soft | guided-hard.

Honesty guarantees carried from the postmortem — fee math always visible before any CTA (CAP-P3); optional data (price APIs) can never block a step (CAP §7.1.4); every error is a structured code with plain-English copy (CAP-E8); nothing depends on analytics being up.
