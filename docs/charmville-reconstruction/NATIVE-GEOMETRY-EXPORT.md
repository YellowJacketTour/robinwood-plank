# Trusted native geometry export

`node scripts/charmville/export-native-geometry.mjs` loads the actual quest template using the pinned local ZQuest212 editor/player binaries. It compiles a separate `GeometryProbe.qst`, runs it headlessly at DMap4/screen63 and reads native ComboS, combo ID and combo type for every active layer/cell. It applies the same current authored clearing as the adventure script. It never replaces the live quest. The compiler include is temporarily swapped under try/finally and restored; do not run another native compile concurrently.

The current export contains176 base cells and176 layer4 cells. `lib/charmville/geometry/native-adventure-d4-s63.json` includes all352 source records, template/probe/player/native-script hashes, a revision and704 eight-pixel quadrants. There are440 conservatively blocked quadrants. The actor spawn is grid(2,9), corresponding to native top-left(16,72). A conservative2x2 quadrant actor footprint fits at that spawn. The server should validate all four occupied quadrants and every movement step against this pinned artifact, never accept geometry supplied by a browser.

Solidity-bit orientation comes from `src/zc/maps.cpp`: x bit8 shifts the bit by2 and y bit8 by1. Thus the bit order is top-left0, bottom-left1, top-right2, bottom-right3. `src/core/combo.h` defines the combo walk field. The probe uses the engine's `GetLayerComboS`, avoiding a guessed parser for the compressed quest format. The existing editor command exports combos but no complete map JSON was found in `src/zq/commands.cpp`.

This is a **conservative static map**, not a complete reproduction of Link movement. It unions solidity from every active layer, so decorative higher layers can reject paths the native engine allows. The16x16 footprint also over-approximates some native collision checks. FFC motion, bridges, water abilities, doors, elevation, moving obstacles and script triggers are not modeled. Cross-screen travel is not authorized by this single-screen export. These limitations must remain explicit in any initial server movement service.

Build evidence is stored under `work/native-geometry/`: probe source, quest, native log and raw JSON. The player writes traces to allegro.log rather than stdout; the builder preserves the previous log, waits for the completion marker and stops only its own spawned player. No connected player report or client collision packet is used to build this manifest.
