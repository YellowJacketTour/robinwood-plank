# Native encounter presentation

`world-encounter.js` accepts only the actual parent at the supported local origins. The parent projects `{type:'charmville:world-encounter',active:true,encounter:{id,speciesId:286,cell:{x,y},hp,maxHp,revision},damageEvent?:{eventId,damage}}` from its authenticated server response. `active:false` clears. Coordinates, species, HP and revisions are bounded; stale revisions are ignored. Missing refresh for 6.5 seconds clears the view.

Native rendering uses the preserved Poochyena PMD walking sheet's idle frame and exact source ground marker, anchored at the authored server cell, only on DMap4/screen63. It draws a proportional health bar from projected HP. A new committed event at a newer revision can show one brief damage number; initial historical events, stale revisions and repeated event IDs cannot replay that effect. This basic damage-only path is event feedback; supported source attack playback is described below. Neither path calculates hits. No creature or inventory mutation originates from this bridge.

The three bridge tests verify baseline suppression, duplicate/stale/foreign rejection, expiry clearing and sequential batch playback with native acknowledgment, including a pre-existing high acknowledgment counter. Native compilation passes. Actual two-account world HP projection and source Poochyena visibility were verified by the shared-scene test. Dynamic encounter roaming and authoritative creature body collisions remain unimplemented.

## Committed companion attack playback

The parent can send `damageEvents` (at most 16, numeric event IDs in ascending order), retaining `damageEvent` compatibility. Each event may include `actorId`, `actorSpeciesId`, `moveId` and `actorCell`. Six explicit mappings are supported: Treecko 277/Pound 1, Torchic 280/Scratch 10, Mudkip 283/Tackle 33, Pikachu 25/Quick Attack 98, Eevee 133/Tackle 33 and Poochyena 286/Tackle 33. Each uses its species' pinned PMD **Attack** sequence; these are researched presentation mappings, not claims of exact Emerald move-animation parity. Other moves retain damage feedback without invented attack art.

`build-committed-attack-sprites.mjs` acquires eighteen exact source PNGs from the existing pinned PMDCollab commit, preserves source hashes, reads animation durations/contact markers, verifies one ground marker per frame, and generates `CommittedAttackFrames.zh`. Treecko has 10 frames, contact tick 8 and total 19; Torchic 11 frames, contact 14 and total 28; Mudkip 10 frames, contact 10 and total 24. Pikachu has 10 frames/contact 7/total 21; Eevee 11/contact 8/total 30; Poochyena 11/contact 10/total 24. All eight source direction rows are available; aim uses cardinal or diagonal rows according to the target displacement. Damage text appears at the source contact marker; authoritative HP remains the received server value throughout.

The bridge queues unseen events and waits for `encounter-effect-ack.txt` after native playback before dispatching another. Initial history is baselined. Effect counters start above existing native/acknowledgment values and require exact acknowledgment equality, preventing stale files from prematurely advancing the queue. Capacity is bounded at 64 pending effects; overflow logs a diagnostic rather than inventing missing attacks.

For a locally identified owned follower, the six-slot UUID file maps the event to its existing trail position. Its walking body is suppressed for attack playback, and the first attack frame is deferred one native frame to avoid drawing both bodies in the ingestion frame. For other players, `actorCell` remains the committed player-origin presentation location because shared authoritative creature positions do not yet exist. There is no fabricated dash through obstacles and no damage calculation in the renderer.

The fresh actual assist browser test passed Treecko/Pound source contact (row 2), exact owned slot 1, and native completion acknowledgment. Its latest recorded example applied 6 damage and preserved shared HP 7/13. This verifies real event wiring and identity matching, **not** a complete frame-by-frame visual matrix. All Torchic/Mudkip directions and diagonal playback still require individual visual review. An attempted synthetic matrix was interrupted by parent polling; its isolated harness then failed to bootstrap. That unpassed branch was removed rather than retained as successful evidence. The actual account test is the current integration evidence.
