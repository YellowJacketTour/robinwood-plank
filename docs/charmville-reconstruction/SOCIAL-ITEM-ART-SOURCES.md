# Social item art sources

Researched September 13, 2026 from primary project and license pages. Research only: no asset packs downloaded, no art imported, no social inventory enabled.

## First basket decision

Follow [FIRST-SOCIAL-CHARM-BASKET.md](FIRST-SOCIAL-CHARM-BASKET.md): Oran Berry, Burning Heart, Bouquet, and a defined prepared meal come before a broad sticker catalog. Artwork represents an inventory object; a reaction animation is another presentation of that same object, not another spendable unit. The following are proposed art directions, not assertions that upstream packs contain exact Charmville items.

| Item | Proposed first artwork | World / basket / post continuity | Unresolved work |
|---|---|---|---|
| Oran Berry | Existing canonical game artwork only after its provenance is checked | Preserve its exact item identity and recognizable shape across pickup, Satchel, Exchange, and stamp | An open emoji berry is not automatically an Oran asset. Existing possession or a source repository does not establish permission to redistribute Pokémon art. |
| Burning Heart | Original heart-shaped crop with leaves and a small flame; consider a licensed generic heart/fire SVG as a starting component | Crop has growth stages; harvested icon retains the same silhouette; post adds a brief flame flutter | Draw the actual plant and harvested object, rather than replacing the crop with a generic reaction glyph. Record any derivative source and license. |
| Bouquet | Begin evaluation with the verified [Twemoji bouquet SVG](https://github.com/jdecked/twemoji/blob/main/assets/svg/1f490.svg), or create original flowers matching the grown ingredients | Same flower colors and wrapping in crafting output and post stamp | CC BY 4.0 graphics credit is required. Match the final recipe; generic bouquet availability does not define ingredients. |
| Prepared meal | Choose one actual recipe first, then draw the matching plate/bowl and ingredients | World meal, inventory icon and post steam animation show the same output | A random food emoji is insufficient. Kenney Food Kit is a 3D candidate for reference/rendering, not a verified ready-made SVG meal. |

Recommended sequence: finish four recognizable static masters, prove their small-size readability together, then animate the post manifestations. Use one visual direction across the basket; do not mix flat Twemoji, outlined OpenMoji, glossy Fluent and pixel LPC in the same four-item set by default.

## Ingestion and presentation pipeline

1. Select only the four basket masters and their necessary growth/ingredient views. Review beside current game art at 24, 32, 48 and 96 CSS pixels on light and dark surfaces. Keep quantity and ownership legible without relying on color.
2. For each selected source, record item ID, source repository/pack, exact upstream file, author, immutable commit or release, source URL, license identifier and text, download date, checksum, and modifications. Record unresolved rights explicitly; do not substitute a repository's code license.
3. Preserve source masters separately from derived exports. Use SVG for flat vector UI masters and appropriate raster sprites for pixel world art. Keep transparent bounds, consistent visual scale and anchor, and a deterministic static fallback. Do not silently rename an item when its art changes.
4. Sanitize imported SVG, removing scripts, external references and unnecessary metadata while preserving a separate provenance record. Optimize only after comparison to the master. Avoid runtime hotlinks or moving `latest` asset URLs; serve a pinned, reviewed subset.
5. Author a short post animation from the same master: flame flutter, bouquet sway, meal steam, or berry glint. Preserve object recognition, avoid endless attention-seeking loops, pause offscreen, and honor reduced motion with the static view. Animation is cosmetic and never triggers another debit or changes receipt identity.
6. Generate accessible credits from the selected-asset manifest. Keep MIT notices, CC author/source/license/change information, and any required derivative-art licensing with distributed outputs. Check licenses again if combining layers from different packs.
7. Validate inventory integration separately: a supported owned item appears in the basket; preview names it and shows quantity; only explicit send produces the server-accepted stamp. Artwork presence is not proof of issuance, custody, post-spend support or persistence.

## Franchise and meme boundary

Nintendo/Pokémon artwork is not automatically licensed by an emulator, decompilation, sprite-tool or fan-project source-code license. Pokémon's [copyright page](https://www.pokemon.com/us/legal/copyright) reserves use except under stated terms or written permission; its [legal information](https://www.pokemon.com/uk/legal/information) expressly says use of fan art by Pokémon does not grant broader use of Pokémon IP. [Nintendo's IP FAQ](https://en-americas-support.nintendo.com/app/answers/detail/a_id/55888/) likewise does not supply an open art license. Treat franchise asset clearance independently from runnable code.

Pepe sticker availability, meme popularity, a token association or an MIT label on a sticker bot also does not establish a license from the image's rights holder. No primary open license for a specific Pepe asset was verified in this research; it is not on the approved source shortlist. Use an original frog character or a specifically licensed generic frog asset for a new creature/item family. This sourcing recommendation does not alter any existing item balances or names.
