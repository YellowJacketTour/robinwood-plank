# Native position observations and correction projection

The native script publishes its current top-left x/y, facing, DMap/screen and real/fake elevation every six script ticks into a latest-value filesystem sample. Coordinates use native decimal formatting rather than tile rounding. `position-observer.js` forwards changed sequences to the allowed parent origins as `charmville:position-observed`, with sessionId, sequence, dmap, screen, x, y, direction, z, fakeZ, appliedCorrectionSequence and authority `local-observation`. This is an observation, not server movement authority; polling may skip intermediate samples.

The parent actor adapter must validate origin and actual iframe, match geometry revision/map, reject unsupported elevation and ask the authenticated actor service to validate movement. The initial service's native grid is8px; its actor footprint is2x2 cells. Only exported DMap4/screen63 is supported. The bridge does not infer a legal path through skipped coordinates or authorize transitions to another map.

Corrections use `charmville:position-correction` with current sessionId, increasing sequence, dmap4, screen63, x/y in bounded8px grid positions, cardinal direction and reason `spawn` or `rejected`. The bridge requires the real parent window and an allowed origin. Native code additionally requires the same current map and grounded actor, then applies coordinates, cancels the local action and clears follower history. It emits the applied correction sequence in subsequent observations so the parent can discard earlier samples. Parent code must send only the position returned by its server actor service; the native bridge does not independently authenticate server replies.

At native run restart, position and correction files are cleared before publishing the new run counter. This prevents stale snapshots or corrections from becoming part of a new run. There is no inventory/reward mutation in this protocol. Incompatible native speed, service cadence or conservative collision can produce corrections; smoothness requires actual measurement, not invented interpolation through blocked cells.

Unit tests cover fractional coordinates, observation deduplication, parent/session validation, bounds, grid alignment and correction sequence replay rejection. `verify-native-party-projection.mjs --positions` is the browser test for actual movement observations and correction acknowledgment. Its test correction is explicitly a projection fixture, not evidence of server-authorized movement.
