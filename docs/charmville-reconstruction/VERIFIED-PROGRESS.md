# Charmville: evidence-based progress and remaining work

Snapshot: 2026-09-12, local working tree. This is a source and checkpoint audit, not a new playthrough, load test or release certification. Existing historical progress bars describe integration maturity, not percentage complete. No percentages are assigned here. An implementation can be server-backed while its artwork and player experience remain unfinished.

## Current product in one sentence

There is a locally connected account, native adventure, three-bed Oran farming loop, companion roster, bounded encounter/capture services and exchange; there is not yet the complete seamless social farming creature civilization MMORPG.

The current entry is `/charmville/world?panel=play`; `/charmville/play` creates a guarded local test identity. The retired standalone garden and rejected frontier are not the target game. Continue from the current native world, preserving saved account custody.

## Status meanings

- **Local playable:** a checkpoint records a visible local interaction; this does not certify every device, direction or interruption.
- **Server-backed:** the inspected code validates and persists a bounded operation; this does not establish a production MMO.
- **Unwired:** a source catalogue, adapter, domain primitive or reference exists but the complete player flow is absent.
- **Planned:** specification only, or substantial necessary implementation is absent.

## Next connected milestones

1. Finish a single authored menu language: Party selection, details, care/follow action and return; then reuse its input/feedback rules for Equipment, Satchel, Map and Exchange. Verify in the same retained browser instance.
2. Complete the family Burning Heart loop: once-only seed grant, clear bed, visible growth, committed harvest, gift another local profile, durable balances and purposeful social animation. Preserve Oran healing and existing saves.
3. Make a complete creature expedition: six owned companions, visible follow/formation, one authoritative wild target, world action and staged battle using one HP/status identity, one capture and durable party/collection return.
4. Connect authored home, public meadow and a friend's home through real geographic transitions with safe spawn/collision and persistent rights. Show another player's committed action, not merely a marker.
5. Add a profession-to-crafting-to-market chain with useful gear, input/output custody and correct tool artwork; expand catalogue only with real acquisition/use/sinks.
6. Prove multiplayer worker/recovery/performance boundaries before broader raids, civic systems and world expansion. Maintain solo, party, competing-party, PvE and explicitly enabled PvP rules for every mutation.

## Verification discipline

This audit ran no game tests and does not certify current browser state. Refer to the specific historical checkpoint for each reported test. Run focused checks after meaningful changes, then the repository's release checks before shipping. Do not repeatedly run broad suites merely to inflate pass counts. Unit correctness, visual acceptance, live interaction, multiplayer behavior and device performance are separate gates. Never fill progress bars from filenames or planned catalog entries.

Historical `CURRENT-STATE.md`, `NEXT-STEPS.md` and long `FEATURE-PROGRESS.md` contain superseded snapshots. Reconcile their newest dated evidence with current source; do not restart obsolete prototypes or treat earlier compiler-only evidence as a present runtime result.
