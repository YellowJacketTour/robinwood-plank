# First player and shared world acceptance

The opening must be a playable homestead, not an equipment laboratory or a list of disconnected features. Normal native arrival now selects a basic sword and three hearts. The explicit endgame diagnostic link remains available. Native equipment is not an issuance of account inventory.

The journey guide must derive home and partner readiness from account responses. It may open the existing setup and admission controls; it must not claim a tutorial completed merely because a button was clicked. Farming completion ultimately needs a durable harvest receipt, companion selection an owned creature, and travel a committed region admission. The current guide is navigation, not the completed scripted tutorial.

## Required next world integration

Current home and public admissions share one 32-by-22-cell geography. The next world milestone requires a server-owned map registry binding each region to geometry revision, spawn and authorized exits. A home exit must atomically validate the actor's position and permission, admit the player to the public region, increment the actor epoch, and return the new map and safe spawn. The client loads that map only after admission. Retries must return the same result; stale native movements and tool contacts must not cross the epoch boundary.

Author two visibly distinct layouts: a sheltered home with readable beds, house entrance and exit; and a public area with meeting space, encounters and a route back. Validate footprints and collision before assigning spawns. Private instance identity must survive shared map art. Friends can only enter with valid permission; revocation cancels actions and removes private observations. Public and private resources remain independently owned and conserved.

Acceptance uses two real authenticated local accounts: owner enters home, visitor joins with permission, both see movement and crop changes, both leave through the exit, meet in the public area, and return without losing inventory or replaying actions. Test concurrent travel, reconnect, rejected admission, touch and controller navigation. Loading states must retain a clear return path and must not describe a rejected move as success.

## Current evidence and limits

The latest audit verified mutual authenticated actor API presence. The existing native movement browser verifier failed with sequence remaining zero after the guide changes; this is not a native movement pass. Remote rendering currently uses standing source tiles, two-second polling and a bounded peer count. Distinct terrain, seamless exits, smooth remote animation, replicated equipment and authoritative native sword combat are not complete. These are required before describing the result as a seamless MMORPG.
