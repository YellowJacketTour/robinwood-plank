# Native Oran resource loop: verified scope

`verify-native-economic-loop` passed locally: an authenticated private account uses three native beds to till, plant, water, wait for the server's 30-second growth period and harvest. One Oran produce and one returned seed are committed. The checked result is three seeds and one produce, visible in the same account inventory and retained after reload. Native animation/contact observations alone do not award goods: the authenticated resource service controls settlement.

Focused PostgreSQL checks cover harvest into exchange escrow, cancellation returning the escrowed item, private permission revocation and duplicate commit handling. Four resource-client tests and four bridge tests passed. This records the tested bounded implementation; it is not an exhaustive test of all directional animation states, production infrastructure or remote-device performance.

The loop uses the new native resource authority, not the retired standalone garden UI. Source crops and local guest counters do not automatically become account assets. This evidence covers the implemented Oran resource only and does not establish a global crop/species catalogue, combat, capture, PvP, fertilizer economics, full crafting graph or universal tool-equipment binding.

Next gates: server-authorized weapon and encounter actions with health/status continuity; authored resource definitions and supply/input/output policies beyond Oran; unified equipment selection tied to owned items and native animations. Multiplayer resource observation and the full visual interruption/facing matrix need their own acceptance evidence. Farming maturity remains locally connected.
