# Ordinary ball capture presentation

The authenticated parent sends `charmville:capture-event` only after a successful capture-action HTTP receipt: `eventId`, locked-server `actorCell` and `targetCell`, `captured`, and `shakes`. This is a committed result animation, not predictive contact or client-side capture resolution. The bridge accepts the actual parent at the two local3017 origins, validates bounded cells and UUID shape, rejects contradictory shake/outcome combinations, deduplicates event IDs, and queues at most8 effects. Native completion acknowledgment controls queue advancement. Signout sends `active:false`; ordinary encounter hiding does not erase the capture effect.

Source is pinned Emerald `5eff78649e7170a877b961ef0b3da13b81a16038`: `graphics/balls/poke.png` and `open.png`, preserved byte-for-byte with hashes under `public/charmville/creatures/capture`. `src/pokeball.c` uses a16px closed/opening/open sequence and patches the ordinary ball's third frame with shared open art. `build-capture-ball.mjs` reproduces that layout for the indexed native runtime. The five-tick opening frame follows source timing; the fully-open hold,24-tick world throw arc and24-tick shake intervals are adapted presentation timing, not claims of exact Emerald battle-camera behavior.

The native sequence throws from receipt actor origin, opens, closes, renders the receipt's0–3 visible shakes, and then displays captured or broke-free. Emerald math success4 means three visible shakes followed by success. A successful receipt can briefly retain the source wild silhouette during the throw even though the authoritative encounter is already hidden; this is only cosmetic continuity. Failed capture shows the live encounter again after release. No currency, balls, creature ownership, damage or random rolls originate here.

Rebuild: `node scripts/charmville/build-capture-ball.mjs`, then `node scripts/charmville/build-homestead.mjs --candidate`; publish after review with the same command without candidate. Reference runtime must load the capture bridge and ball whitelist. `node --test scripts/charmville/capture-bridge.test.mjs` covers invalid/foreign/duplicate outcomes, queue serialization, exact acknowledgment and clearing. Native candidate/publish compiles pass. Actual receipt-driven browser verification passed: one failed throw followed by success emitted native START, OPEN and RESULT markers and completion acknowledgments, using real server receipts. The first attempt to run this check exposed a missing module whitelist route; that route was fixed and HTTP200 verified before the successful rerun. The result screenshot is postanimation, not proof of individual ball frames. A timed `--capture-visual` fixture exists, but its initial run was blocked by3017 being offline during the production build and has not been counted as passed.

Limits: ordinary ball and current Poochyena encounter only; no source throw-arm pose, absorption particles, capture audio, variants, prospective windup authority, or spectator capture-event replication yet. Current HP/ownership remain server state throughout. Full frame-by-frame visual review remains outstanding.
