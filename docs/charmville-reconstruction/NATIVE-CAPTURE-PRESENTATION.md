# Ordinary ball capture presentation

The authenticated parent sends `charmville:capture-event` only after a successful capture-action HTTP receipt: `eventId`, locked-server `actorCell` and `targetCell`, `captured`, and `shakes`. This is a committed result animation, not predictive contact or client-side capture resolution. The bridge accepts the actual parent at the two local3017 origins, validates bounded cells and UUID shape, rejects contradictory shake/outcome combinations, deduplicates event IDs, and queues at most8 effects. Native completion acknowledgment controls queue advancement. Signout sends `active:false`; ordinary encounter hiding does not erase the capture effect.

Source is pinned Emerald `5eff78649e7170a877b961ef0b3da13b81a16038`: `graphics/balls/poke.png` and `open.png`, preserved byte-for-byte with hashes under `public/charmville/creatures/capture`. `src/pokeball.c` uses a16px closed/opening/open sequence and patches the ordinary ball's third frame with shared open art. `build-capture-ball.mjs` reproduces that layout for the indexed native runtime. The five-tick opening frame follows source timing; the fully-open hold,24-tick world throw arc and24-tick shake intervals are adapted presentation timing, not claims of exact Emerald battle-camera behavior.

The native sequence throws from receipt actor origin, opens, closes, renders the receipt's0 to 3 visible shakes, and then displays captured or broke-free. Emerald math success4 means three visible shakes followed by success. A successful receipt can briefly retain the source wild silhouette during the throw even though the authoritative encounter is already hidden; this is only cosmetic continuity. Failed capture shows the live encounter again after release. No currency, balls, creature ownership, damage or random rolls originate here.

Rebuild: `node scripts/charmville/build-capture-ball.mjs`, then `node scripts/charmville/build-homestead.mjs --candidate`; publish after review with the same command without candidate. Reference runtime must load the capture bridge and ball whitelist. `node --test scripts/charmville/capture-bridge.test.mjs` covers invalid/foreign/duplicate outcomes, queue serialization, exact acknowledgment and clearing. Native candidate/publish compiles pass. ## Fullscreen input and character pose audit

The existing Enter/Game menu now offers **Throw ball**. It is disabled unless the actual parent projects current capture availability. Clicking it sends only a capture-request intent and immediately disables the button; the parent uses the same guarded server action as the ordinary capture panel. It does not leave fullscreen or repurpose sword, interaction or other combat keys. Existing menu arrow/controller navigation remains the access path, and disabled choices are skipped.

`probe-native-throw-poses.mjs` compiles an isolated source-quest probe and restores the runtime include afterward. The36 pose/direction results are preserved in `native-throw-pose-audit.json`. The source engine has no dedicated throw-state enum; this quest's lifting27 and liftwalk28 banks are tile0 in all four directions. Casting10 resolves to the same tile33 for all directions. Consequently no lift/cast animation was substituted for an authentic directional throwing arm. A compatible authored throw sequence and hand-anchor mapping remain needed; ball-flight presentation itself is implemented.
