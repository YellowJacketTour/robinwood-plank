# One coherent playable foundation

Priority decision: 2026-09-12. The user explicitly accepts completing the single-player foundation first, provided it remains the foundation of the unified multiplayer game. This changes sequencing, not the ultimate scope. The retired garden and an isolated reference quest are not substitutes for this journey.

This document was produced by source/document inspection only. No new test or live observation is claimed here. Existing evidence below is attributed to recorded checkpoints; the current pilot must establish its own runtime revision and outcomes.

## What counts as the foundation

One player enters through PlankSpace, arrives in an authored home, understands movement and interaction, cultivates and uses a real owned harvest, chooses and walks with a companion, completes a creature expedition, returns safely, and resumes after closing the game. Menus, camera, sound, artwork, custody and story must describe that same world throughout.

Single-player acceptance can run against the existing local authoritative services using a synthetic account. It does not require replacing those services with browser-only balances. If an offline mode is introduced later, its save authority, synchronization and migration must be explicit; guest counters must never silently become account inventory. No wallets, seed phrases, real signatures or real-money purchases are needed for this acceptance.

Keep one primary browser tab and account for the visible journey. A fresh synthetic account may be required to exercise first-time grants or the six-party fixture; identify that change in the evidence instead of overwriting the retained player's progress. A second independently authenticated client is reserved for later multiplayer checks, not an accidental second controller of the same character.

## Menu, art and device acceptance applies to every gate

- One menu shell: world context → category → selection/details → valid action → result → back to the same world. Party, Equipment, Satchel, Map, Charmdex and social tools share focus/back behavior and meaningful art. A menu cannot promise an action that is unavailable without explaining why.
- Keep artwork anchors and meanings consistent: body/tool/shield pose, ground position, projectile origin, hit window, pickup identity, target state and UI item illustration. Audit north/south/east/west, foreground occlusion, interruption and screen return. A successful compile does not accept an animation.
- Keyboard, touch and controller require separate real interaction evidence. Fullscreen/resize/zoom must preserve readable HUD, reachable controls, aspect ratio and input coordinates; opening menus must not accidentally attack or move. Actual held input is required for movement evidence.
- Record representative frame pacing and service delays during the accepted journey. No “all devices,” zero-latency or population claim follows from one desktop screenshot. Accessibility needs selection cues beyond color, legible text, predictable back and reduced-motion handling as menus evolve.

## Architecture that stays open to the complete stack

Preserve stable profile, region, entity, creature-instance, crop, item and receipt identities. Presentation coordinates and facing are not custody or world authority. One trusted action result settles inventory/HP/capture; multiple views observe that result. The solo journey is the first consumer of these contracts, not a separate set of hardcoded rewards.

Retain explicit public/private/visitor permissions, action ordering and reconnect semantics while deferring large-population acceptance. Companions, NPCs and spectators must not be counted as independent loot-eligible players. Later party participation, competing-party capture rights, PvP consent and personal party drops extend the same encounter contract. World expansion requires authored exits, safe admission and camera/collision coherence before a larger atlas is called a seamless world.

Keep art and themes replaceable by versioned packs with provenance, anchors, direction/frame bindings and validation. Creator tools should preview real gameplay assets and preserve meanings and custody. Networking, streaming, farming, professions, civic building, raids and space remain in the full scope; they must not displace the currently broken walk → interact → reward → resume chain.

## Proof record per accepted gate

Record timestamp, profile alias, retained tab, app revision, actual content hash, region/map and action sequence; state the observed result and any remaining defect. Pair visible evidence with the relevant movement/action/receipt log interval without exposing bearer tokens or credentials. Distinguish source inspection, focused correctness checks, visible solo acceptance, independent multiplayer acceptance and device/performance acceptance.

Do not generate percentage progress from file counts or historic checklists. Do not rerun the entire suite after each cosmetic change. Use focused checks for changed authority/identity paths, actual play for behavior/art, then required repository release checks before shipping.
