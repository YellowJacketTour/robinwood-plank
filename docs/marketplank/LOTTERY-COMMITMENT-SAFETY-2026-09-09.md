# Frozen board terms and rolling-state integrity

The lottery commits the winner payout and reseed amount together with `committedPrize` at the end of the preceding draw. `quote()` returns those committed amounts. `hitThreshold(rake, committedPrize)` prices that exact winner payout, including for the numbered lottery. Live progression affects the next commitment. `carve(prize)` remains a hypothetical calculation using current progression, so it must not replace `quote()` for a live board.

This closes a timing dependency: after crash progression reaches the spillover threshold, a permissionless one-wei `fundVault()` call can advance lottery progression. Previously that changed the current board's payout and threshold after randomness was available. Numbered rounding could additionally change the ball count and remap the same random word. The regression tests use the actual public donation entry point after publication of mock entropy, with storage fast-forward only to establish the mature fixture. They require unchanged current quote, threshold and ball count, successful settlement, and balance conservation for both lottery versions.

The browser reads each round's ID, body, seats, user stake, target and chain timestamp at one block. It discards responses from a replaced connection and snapshots whose block hash changed. Lottery quotes similarly use one block and the contract's exact net-rake arithmetic. This is coherent observed-chain state, not a claim of finality: later reorganizations remain possible. Presentation interpolates a labelled replay of a settled result; animation does not determine payouts.

The browser refund helper uses `revealNotBefore + refundTimeoutSeconds`, matching the contract. Failed lock, settlement and refund attempts release their retry guards instead of permanently abandoning the current round.

The 96-round deterministic contract soak includes ordinary settlements, actual lottery wins, empty-round voids, and beacon-timeout refunds. It verifies next-round creation, balance accounting and nondecreasing protected principal after every round. Finite testing cannot establish infinite availability. Keeper gas, sequencer availability, beacon service and operational recovery remain external dependencies.

These changes require new contract deployments; existing immutable deployments are not updated by changing these sources. The local test stack uses the new contracts. Independent review and production evidence remain required. In particular, pool redistribution can reward strategic target portfolios; the existing aggregate funding caps do not imply every player has the same expected return or receives a guaranteed target multiplier. Protected principal, spendable reserves and lottery prize pools are distinct: a paid lottery pool can decrease, and universal positive expected returns cannot be sustainably promised from player deposits alone.
